# Kick Chat (Go, OAuth)

Консольная отправка сообщений в чат Kick через **OAuth** и [kick-go-sdk](https://github.com/henrikah/kick-go-sdk) v2.1.0. Без куков — только официальный API.

**Как всё запустить (Kick Chat, Next.js дашборд, License Server):** см. [LAUNCH.md](LAUNCH.md).

## Требования

- Go 1.21+
- OAuth-приложение на [developers.kick.com](https://developers.kick.com/)

## Регистрация приложения

1. Зайди на [developers.kick.com](https://developers.kick.com/) и создай приложение.
2. Укажи **Redirect URL**: `http://localhost:8765/callback`
3. Включи scope **chat:write**.
4. Сохрани **Client ID** и **Client Secret**.

## Установка

```bash
cd Kick-Chat-Go
cp .env.example .env
# Заполни .env: KICK_CLIENT_ID, KICK_CLIENT_SECRET
go mod tidy
go build -o kick-chat-go .
```

## Запуск

```bash
./kick-chat-go
# или
go run .
```

При первом запуске:

1. В консоли появится ссылка для авторизации.
2. Открой её в браузере, войди в Kick и разреши доступ (channel:read, chat:write).
3. После редиректа токен сохранится в `.kick_accounts.json` как первый аккаунт.
4. Дальше вводи сообщения и нажимай Enter — они отправляются в чат от текущего аккаунта.

### Несколько аккаунтов

- **`use 1`**, **`use 2`** … — переключить текущий аккаунт по номеру.
- **`accounts`** (или **`list`**) — список аккаунтов и текущий.
- **`add`** — добавить новый аккаунт (откроется OAuth в браузере).

Токены хранятся в `.kick_accounts.json`. Выбранный аккаунт запоминается между запусками.

### SOCKS5-прокси

Формат: `host:port:user:pass`. Запросы к API Kick идут через прокси текущего аккаунта.

- Файл **`.kick_proxies`** — по одной строке на аккаунт (строка 1 → аккаунт 1, строка 2 → аккаунт 2 и т.д.). При запуске пустые прокси в аккаунтах заполняются из этого файла.
- Прокси можно задать и вручную в `.kick_accounts.json` (поле `"proxy": "host:port:user:pass"` у каждого аккаунта).

### Веб-дашборд

При запуске поднимается дашборд: **http://localhost:8080** (порт задаётся через `DASHBOARD_PORT`).

- **Слева** — оригинальный чат Kick (iframe канала).
- **По центру** — трансляция (embed плеера Kick).
- **Справа** — список аккаунтов и статус «онлайн» (прокси живой и токен валидный).
- **Под трансляцией** — выбор аккаунта, поле ввода сообщения и кнопка «Отправить».

Сообщения отправляются от выбранного аккаунта. Список аккаунтов и статусы обновляются раз в 30 секунд.

Переменные окружения (или `.env`):

| Переменная | Описание |
|------------|----------|
| `KICK_CLIENT_ID` | Client ID приложения (обязательно) |
| `KICK_CLIENT_SECRET` | Client Secret (обязательно) |
| `KICK_REDIRECT_URI` | Redirect URL (по умолчанию `http://localhost:8765/callback`) |
| `CHANNEL_SLUG` | Slug канала (по умолчанию `mlaffonxd`) |
| `KICK_ACCESS_TOKEN` | Токен для импорта как первый аккаунт при пустом списке (опционально) |
| `DASHBOARD_PORT` | Порт веб-дашборда (по умолчанию `8080`) |

## Распространение (без исходного кода)

Чтобы отдать программу кому-то «просто запустить»:

1. **Собери бинарник:**  
   - На Windows: `go build -o kick-chat.exe .`  
   - На Mac/Linux: `go build -o kick-chat .`  
   Если собираешь на Mac/Linux **под Windows** (кросс-компиляция):  
   `GOOS=windows GOARCH=amd64 go build -o kick-chat.exe .`  
   (Go нужен только тебе, кто собирает.)
2. **Отдай пользователю:** один файл `kick-chat.exe` (на Windows) или `kick-chat` (Mac/Linux) и копию `.env.example` (пусть переименует в `.env`).
3. **Пользователь правит только `.env`:** подставляет свой **канал** (`CHANNEL_SLUG`), **Client ID** и **Client Secret** от своего приложения на [developers.kick.com](https://developers.kick.com/). Остальной код не нужен — всё уже внутри бинарника.
4. **Запуск:** пользователь просто запускает бинарник (на Windows — двойной клик по `kick-chat.exe` или `kick-chat.exe` из cmd; на Mac/Linux — `./kick-chat`). **Устанавливать Go не нужно** — он нужен только для сборки, не для запуска.
5. **Файл `.kick_accounts.json` отдавать не нужно.** Он создаётся сам при первом добавлении аккаунта (кнопка «+» в дашборде → OAuth). У каждого пользователя будут свои аккаунты и токены. При необходимости прокси настраиваются в дашборде или через файл `.kick_proxies` (создаётся пользователем).

Исходники Go и встроенный интерфейс дашборда распространять не обязательно. Логика работы (аккаунты, прокси, отправка в чат) выполняется внутри бинарника и недоступна для просмотра.

## Отличие от Node-версии

- **Node (Kick-Chat-Manager)**: куки + SOCKS5, много аккаунтов, WebSocket + HTTP send.
- **Go (Kick-Chat-Go)**: несколько аккаунтов (OAuth), переключение через `use N`, официальный API, консольный ввод.
